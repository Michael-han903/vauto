## 2. 实测业务要点（影响后续设计）

1. **无转场/加载页面**：不需要 loading 检测，流程少一步。

2. **车库车辆列表用鼠标滚轮上下翻页**：
   - B 流程遍历车辆时需用滚轮滚动（`InputSimulator.scroll`）；
   - 列表项模板取"列表项图标本身"这种跨滚动位置通用的元素，
     裁剪时避开选中高亮/光标；
   - 列表项可能在任意滚动位置出现，模板匹配是全局搜索，不受影响。

3. **每台车技能树页面布局/位置不一样**：
   - 不能依赖绝对坐标定位节点；
   - 节点识别取"节点图标"这类跨车通用元素，或按车分别校准；
   - 配合 ROI 限定搜索区域 + 颜色判据（第 6 步 ROIClassifier）。

4. **解锁操作是键盘确认（不是点击节点）**：
   - 进入车辆精通页面后，选中节点按 **Y** 键，再按 **回车** 确认，
     技能点足够即解锁；
   - 业务组装时解锁动作用 `tap_key("y")` + `tap_key("enter")`；
   - 技能点不足时确认无效，应出现 `popup_no_resource` 弹窗（已录素材）。

## 3. 流程录屏实测补充（2026-10-02 18:47，11 分 35 秒 / 4K / 30fps）

素材：`屏幕录制 2026-10-02 184716.mp4`。用 `calibrate.py` 标定出的阈值+ROI 逐帧扫描得到界面时间线，
详见 `docs/流程录屏时间线.md`。以下为影响设计的硬事实：

1. **本轮挑战的车辆**：`1998 斯巴鲁 Impreza 22B-STI Version`（S2 834，传奇，价值 313,500）。
   跑 A 之前**当前车辆必须是它**。

2. **首次进入挑战要 5 步菜单**（不是自动的）：
   主菜单 → 创意中心 → EventLab 赛事浏览 → 搜索（共享代码 **161047605**）→ 确认 → 加载 → 起跑线。
   之后每一轮按 **Esc** 就能重开同一赛事，这就是"连续跑四五次"的做法。

3. **一轮约 9 分钟**：0:24 起跑 → 9:26 出现结算（542 秒）。赛事标题写的是 8MIN。

4. **结算态判据（实测在录屏上命中）**：全屏蓝色旗帜「挑战完成！」+ 左下提示条
   `[Enter] 继续  [Esc] 重试`。`hint_esc_retry` 得分 0.991（阈值 0.878）、`panel_result` 0.641（阈值 0.535）。

5. **`Y 解锁全部` 是"整页一键解锁"，且会弹确认框**：
   黄色对话框「解锁该车辆的所有额外加成？」→ 选「**解锁额外加成**」→ 才真正解锁。
   即动作序列为 **Y → Enter（确认）**（与第 2 节第 4 条一致，此处补上"确认框"这一环）。

6. **"这台车做完了"的判据**：解锁成功后，该页节点全部变亮、可用点数下降，
   且底部提示条里的 `[Y] 解锁全部` **消失**（只剩 `[Esc] 返回`）。
   实测 `hint_unlock_all`：未解锁页 0.996 命中 → 解锁后不命中。这是最可靠的"本页已完成"信号。

7. **花费不固定**：实测两页分别花掉 55 点（195→140）与 94 点（160→66），
   所以"会不会一次花光"取决于该页各节点价格之和 —— 与用户描述一致。

8. **技能点上限 999**。

9. **`车辆熟练度` 打开的是"当前车辆"的精通页** —— 因此做 B 会改掉"当前车辆"，
   而 A 必须用 22B。**B 收尾（或进 A 之前）必须把当前车辆切回 1998 斯巴鲁 Impreza 22B-STI Version。**
   这是整条流程里最容易出错、后果最直接的一步。

10. **B 的遍历方式（用户口径）**：要么从头一辆一辆看，要么记住上一次点到哪里。
    实现上建议：默认从列表头扫，遇到"提示条已无 `[Y] 解锁全部`"的车直接跳过；
    另设 `--resume` 持久化上次位置。

11. **界面里存在第三方性能悬浮窗**（右上角「142 显卡: 76%」），全程都有；
    现有 ROI 都不在右上角，不受影响，但正式跑建议关掉以减少变量。

12. **判据语义注意**：`hint_esc_back` 匹配的是提示条前两格（`Enter 选择 | Esc 返回`），
    主菜单/车库/精通页都一样能命中 —— 它只能当"菜单提示条存在"的健全性检查，
    **不能用来识别具体页面**。页面识别请用 `page_title_garage` / `page_title_mastery`。

## 4. 挑战阶段的实际输入 & 车库列表导航（2026-10-02 用户口述）

### 4.1 挑战进行中

- **只需要一直按住 `W`**，时间到游戏自动结束（约 9 分钟一轮）。
- 一轮结束后按一次 `Esc` = 重试（重开同一赛事）；按 `Enter` = 继续（离开赛事）。
- 首次进入赛事要 5 步菜单：主菜单 → 创意中心 → EventLab → 搜索 → 共享代码 **161047605**。

### 4.2 「更换车辆」/「我的车辆」列表的导航规则（重要）

1. **列优先填充**：车辆按列从上往下排满一列，再排下一列；**列高不固定**（1 辆 ~ 5 辆都可能）。
2. `↓` = 本列下一辆。
3. `→` = 下一列。
4. 列走到底还按 `↓`，游戏会**跳到附近最近的那个"不是该高度"的列**的「第 (行号+1) 辆」：
   - 单辆车的列（选中第 1 辆）按 `↓` → 跳到最近的非单辆车列的**第 2 辆**；
   - 两辆车的列（选中第 2 辆）按 `↓` → 跳到最近的非两辆车列的**第 3 辆**。

**由此推出的结论**：光按 `↓` 会**漏车**（模拟验证：列表 (1,3,1,2) 从第 1 辆开始只按 ↓，只走到 3/7 辆）。
而且程序只看得到"车名区域像素"，看不到光标在第几列第几行，**无法事先算出该按 ↓ 还是 →**。

### 4.3 程序采用的走法（`flow/nav.py`，已用模拟器量过）

每步都验证：**按 `↓` → 车名区域变了？没变就按 `→` → 还没变再试一次 → 连续 3 步换不动就认定到边界**。
在 300 个随机列表 × 随机起点上的实测（步数预算 24 步）：

| 按键策略 | 列表覆盖 | 步数效率（新脸/步） |
|---|---|---|
| **P1 ↓优先、→兜底（采用）** | 37.7% | **49.4%** |
| P2 ↓优先、→兜底、再试 ↑→ | 39.4% | 19.5% |
| P3 →优先、↓兜底 | 41.1% | 21.3% |

**为什么覆盖率只有 ~38% 也可以接受**：
- B 轮的**真正退出条件是「不够支付全部」弹窗（技能点不足）**，不是"把列表走完"；
- **重访已解锁的车是零消耗的 no-op**（`hint_unlock_all` 不在 → 直接返回，不按 Y）；
- 每次 B 会话只处理几台车（点数够多少就点多少），不是扫全表。

要走 **100% 覆盖**需要"位置感知"（识别选中格的高亮位置 → 下方有车就 ↓、没有就 →），
这需要一张能同时看到"选中格 + 空格"的 `更换车辆` 列表截图，属于可选的第二步。

### 4.4 上车后的落点：**主世界（自由驾驶）**，不是任何菜单页（2026-10-02 用户实测确认）

用户明确：「每一辆车点击上车之后都会回到主世界，要点一下 esc 才能到有车辆标签页的那个界面。」

所以换车的完整键盘/鼠标链是：

```
点「更换车辆」→ ↓ 走一格 → Enter（选择操作）→ Enter（上车）
   → [加载 13~18s] → **主世界（自由驾驶）**
   → Esc → 主菜单（可能停在别的标签页）
   → 鼠标点「车辆」标签 → 车辆页（tile_mastery 出现）→ 点「车辆熟练度」→ 精通页
```

`flow/runner.py` 按此实现：`_ensure_vehicle_tab(after_load=True)` **先按 Esc**（而不是先点
标签 —— 在主世界里点标签毫无意义），然后用 `_in_menu_now()`（左上菜单车名面板
`car_current_menu` / 车辆页磁贴 / 车库标题三个判据）判断"在不在菜单里"，决定下一步是
点标签还是再按 Esc，最多 4 轮，每轮的判据分数写进 `ensure_tab_probe` 日志。
若上一步其实停在「我的车辆」列表页，则先 Esc 退出来再点标签。

### 4.5 「车换了吗」这个判据不能用左上角名条（2026-10-02 真跑翻车 + 实测复现）

第一次真跑（`--phase spend --cars 1 --live`，日志 `logs/run_20261002_204327_live.jsonl`）
在**走一格**这步失败：按了 ↓ → → ↓ → 每次都被判成"没变化"，走格子策略判定"走不动了"退出。

根因：当时用**左上角「当前车辆」名条**（ROI `68,48,1356,136`）做换车验证。实测复现
（`golden_frames/garage_list` 的 44 张连续帧，用户当时正在这页操作）：

| 比较区域 | 43 对相邻帧的差值 |
|---|---|
| 左上角名条（旧判据） | 平均绝对差 **全部 0.00** —— 光标移动它完全不变（它显示"当前驾驶的车"） |
| 列表区域（新判据，`0,400,3840,1520`） | **分块最大差 18~152** |

所以：**名条是死的，列表区域才是活的**。而且整屏平均差对"挪一个高亮框"不敏感
（0.6 量级，任何阈值都判不出来），必须用**分块最大差**（把区域切成 8×6 块取最大）
—— 这个指标已进工具层：`vauto.vision.block_max_abs_diff`，阈值 6.0。

同时修掉一个更隐蔽的错：**"列表打开了吗"原来用名条判** —— 而名条在「车辆」标签页上
也有（此页 0.684 阈值下 1.000），等于没判。现在用 `page_title_garage`（「我的车辆」
页面标题，只在列表页出现）。

回归测试：`selftest_flow.py` 第 ⑤ 节用这 44 张真实帧把上面的结论钉死
（名条最大均差 < 1.0；列表分块最大差最小值 > 阈值×2）。

## 5. 判据的语义边界：**带业务对象的模板不能当页面判据**（2026-10-02 --cars 3 跑挂的根因）

`car_current_menu`（主菜单左上那块车名面板）和 `car_current_garage`（车库左上名条）这两张
模板，**连车图 + 车名 + 等级徽章一起裁进去了**。所以它们的真实语义是：

> "**当前这辆车**是 1998 斯巴鲁 Impreza 22B-STI，而且我在主菜单/车库页"

而不是"我在不在菜单里"。B 流程把当前车换成了 **Abarth 695 Biposto**（用户截图确认），
于是 `car_current_menu` 只有 **0.508**（阈值 0.799）→ 程序判定"不在菜单里"→ 反复按 Esc
在 主世界 ↔ 剧情页 之间来回切 → `vehicle_tab_fail`。

**修法**：新增两个**与当前车辆无关**的判据，专门回答"我在不在菜单系统里"：

| 判据 | 内容 | 为什么可靠 |
|---|---|---|
| `tile_collection` | 剧情页「收集簿」磁贴白字（**用户建议**） | 从主世界按 Esc，菜单**总是开在剧情页**（所有实测截图都是 剧情 高亮），收集簿只在这一页、与车无关 |

**试过但废弃的：`tabbar_main`（标签栏）**。裁了「剧情…创意中心」一整条，结果正样本 min 只有
0.376 —— 因为**选中标签是黑底高亮**的，换一个标签页整条纹路就变。教训同上：判据必须挑
"跨状态不变"的部分。收集簿是静态磁贴，实测才立得住：

| 对照 | ROI 内分数 |
|---|---|
| 正样本（剧情页截图 entry_01） | **1.0000** |
| 125 帧负样本 max（含录屏主菜单帧、创意中心页） | **0.3211** |
| 实际装配阈值 | **0.75**（上余量 0.43 / 下余量 0.25） |

它只登记在 `templates/manual_thresholds.json`（手工），因为正样本只有 1 帧全帧素材，
达不到 `calibrate.py` 的"正负各 ≥3 帧"闸门。

`car_current_menu` / `car_current_garage` 仍然保留，但只用于"当前车是不是 22B"这一件事。

**一般教训（写进设计守则）**：判据 ROI 里只要含**会变的业务对象**（车图、车名、技能点数、
任务进度、玩家昵称/货币），它就只能用来判断那个对象，**不能**用来判断"我在哪个界面"。
要判断界面，必须挑界面上**固定不变**的那部分（标签文字、页面标题、静态磁贴）。

## 7. 判据探针（`run_vauto.py --probe`）

标定证明「素材上分得开」，探针证明「实机上没认错」——两者是两道独立验收：

- 只抓帧打分、**绝不按键**；人工翻页面时每 2 秒打印当前画面每个判据的分数；
- Ctrl+C 后输出「最高分 / 通过帧数 / 结论（✅稳 / ⚠️擦边 / ❌没出现）」汇总；
- 每个判据**首次命中**时自动存下该帧的 ROI 截图到 `debug_frames/probe/<name>__first_pass.png`，
  用来人工确认「它认的到底是不是我以为的那个东西」。

实测一次（2026-10-02 20:30，游戏停在主菜单、当前车 = 22B）：
`car_current_menu = 1.000`（阈值 0.799）连续 46 帧全部命中，
而 `hint_esc_retry = 0.757`（阈值 0.880）、`popup_confirm = 0.820`（阈值 0.913）都没误报
→ 主菜单这一屏上三个判据的分离是干净的。

### 7.1 实机复核结论（2026-10-02 20:52，620 帧 / 99 秒，用户手动翻页）

用户按「主菜单 → 车辆 → 更换车辆 → ↓ → 选择操作 → 上车 → 车辆熟练度 → Y → Enter」
走了一遍，全部判据在**实机**上通过：

| 判据 | 阈值 | 实测最高 | 命中帧 | 结论 |
|---|---|---|---|---|
| `menu_select_title`（选择操作标题条，**手工推定**） | 0.750 | **1.000** | 4 | ✅ 推定值成立，且全屏只在菜单弹出时命中 |
| `option_enter_car`（上车行，**手工推定**） | 0.850 | **1.000** | 3 | ✅ 推定值成立，与标题条**同帧同时命中**（互相印证） |
| `popup_no_resource`（不够支付全部） | 0.626 | 1.000 | 102 | ✅ 余量 0.374 |
| `popup_confirm`（确认提示条） | 0.913 | 0.997 | 101 | ✅ 余量 0.084（弹窗期间 0.997，平时 0.820~0.825） |
| `hint_unlock_all`（[Y] 解锁全部） | 0.805 | 0.999 | 44 | ✅ 精通页有可解锁时稳定命中 |
| `page_title_garage` / `page_title_mastery` | 0.678 / 0.700 | 1.000 | 104 / 73 | ✅ |
| `car_current_menu` / `car_current_garage` | 0.799 / 0.684 | 1.000 | 94 / 85 | ✅ |
| `tile_change_car` / `tile_mastery` | 0.628 / 0.620 | 1.000 | 62 / 61 | ✅ |
| `hint_esc_retry` / `panel_result`（本轮没进挑战） | 0.880 / 0.577 | 0.757 / 0.164 | 0 | ✅ 全程未误报 |
