### 0.4 第二次真跑（2026-10-02 20:51）走通了 B 的完整一步

`--phase spend --cars 1 --live` 实际动作链（`logs/run_20261002_2051*.jsonl`）：

```
点「车辆」标签(1390,460) → 点「更换车辆」(1260,760) → ↓（分块差 149.0 ✔ 换车验证命中）
→ Enter（选择操作）→ Enter（上车）→ 等加载 → 点「车辆熟练度」(1285,1292)
→ mastery_already（这台车早解锁过，跳过）→ Esc 收尾
```

两点结论：
1. **新的换车验证判据一次命中**：分块最大差 149.0（阈值 6.0，余量 25 倍）。
2. **"重访已解锁车是零消耗"这条设计被实机验证**：走到的那台车精通页没有 `[Y] 解锁全部`
   → 直接 `mastery_already` → Esc → 下一台，没有按 Y，没有消耗点数。
3. **暴露一个自动化缺口（已修）**：上车后游戏**不保证**停在「车辆」标签页 —— 实测落回了
   「我的车辆」列表页，那一下「车辆」标签是**用户手动点的**（日志里没有程序点击记录）。
   原因：`change_car()` 上车后只是被动 `_wait_for("tile_mastery")`，没有主动切回去。
   现在改成：加载完先单帧判页（`after_load_page` 日志记下在哪一页 + 各判据分数）→
   若在列表页先 `Esc` → 再主动点「车辆」标签 → 验证；`unlock_current_car()` 进来前也先
   确保在车辆页。同时 `_ensure_vehicle_tab()` 改成 probe 快速判断，已在车辆页就不白点。

结论：**你在游戏里把赛事开起来（或停在结算重试循环里），程序可以接手全自动跑 A↔B。**

## 3. 放开跑

```bash
py -3.14 run_vauto.py --title "Forza Horizon 6" --phase farm --rounds 4 --live
py -3.14 run_vauto.py --title "Forza Horizon 6" --phase spend --cars 6 --live
```
- `--phase farm --rounds 4`：连跑 4 轮（最后一轮结束按 Enter 离开赛事）
- `--phase spend --cars 6`：从「车辆」→「更换车辆」往下走 6 台车，逐台解锁；
  一旦弹出「不够支付全部」就停下并提示回 A 刷点
- `--phase both`：先 farm 再 spend（**注意**：spend 会把当前车辆换成别的车，
  再跑 farm 之前必须手动把车换回 1998 斯巴鲁 Impreza 22B-STI）

## 4. 按键与动作对照表

| 键 / 操作 | 什么时候 | 干什么 |
|---|---|---|
| W（按住不放） | 赛事加载完 → 结算出现 | 挑战进行中的唯一输入 |
| Esc | 结算画面 / 从子页面返回 | 重试（重开赛事）/ 返回上一级 |
| Enter | 结算画面 / 选择操作菜单 / 精通页确认框 / 弹窗 | 继续（离开赛事）/ 选「上车」/ 确认解锁 / 关弹窗 |
| Y | 精通页且提示条有 `[Y] 解锁全部` | 一键解锁本页全部额外加成 |
| 鼠标左键 | 主菜单：「车辆」标签、「更换车辆」磁贴、「车辆熟练度」磁贴 | 导航（会走贝塞尔轨迹 + 落点抖动） |
| 方向键 | 「更换车辆」列表 | 选车（每步都用像素变化验证，见 `flow/nav.py`） |
| F1（只监听） | 任何时候你手按 | 全局急停：停手 + 释放所有按下的键 |

## 5. 出事怎么办

- **按 F1**：立刻中止，并松开包括那只一直按着的 W。
- **Ctrl+C**：终端里也能中断。
- 目标窗口切到后台：所有动作自动暂停（不会盲按），切回来继续。
- 日志在 `logs/run_*.jsonl`，每一条动作/判据都在里面；台账在 `logs/ledger.json`。
- 想复盘"上一轮为什么停"：看日志最后的 `settle / retry_ack / car_ok / no_points` 事件。

## 全自动闭环：`--cycles` / `--cars 0`

```powershell
# 无人值守：进赛事 → 跑 2 轮 → B 一直解锁到「技能点不足」→ 换回 22B → 再来一遍（共 2 轮）
py -3.14 run_vauto.py --title "Forza Horizon 6" --phase both --cycles 2 --rounds 2 --cars 0 --enter-event --live
```

* `--cycles N`：主循环次数（默认 1）。每一轮 = 进赛事 → 跑 `--rounds` 轮 → B 解锁 →
  换回 22B；上一轮 B 刷到「技能点不足」就自动回头跑挑战，**不需要手动重跑命令**。
* `--cars 0`：B 阶段**一直解锁到「技能点不足」、或扫完列表绕回开头**（正常结束条件只有这两个）。
  另有 `cars_cap`（默认 100000）纯粹是**防死循环保险丝**，真打到会醒目告警、别当正常收工。
  `--cars 6` 这类正数 = 最多处理 6 台。
* 一轮 B 一页都没解锁 → 认为所有车都点完了，自动停（不再空刷挑战）。
* 换车（B 结束回 22B）会扫车库列表，实测约 **1 秒/列**、22B 在第 369 列 ≈ 6 分钟；
  终端每 25 列打一行「已扫 N 列」，这期间安静是正常的。

## 卡住了它会自己退回来（自愈层）

以前：停在没人预期的界面（误触进的「查看车辆」、别人的弹窗）时会**继续按计划里的键**，
越走越远，日志里只剩一串看不懂的按键 —— 这就是"莫名其妙"的主要来源。

现在：任何一步认不出界面时，先问自己"**我在哪一屏**"（用现有判据的分数向量贴标签），
再按标签选动作（弹窗按它自己的关法、其余 Esc 退一层），每次按完重新判。
铁律不变：**认不出的时候绝不按回车**。

看日志时找 `recover_probe` / `recover_done` 两条事件，就能知道当时卡在哪、退到哪了。

## 焦点切出去 / 切回来（2026-10-04，用户要求）

他把焦点切到别的程序去做别的事时，以前会出现"切回来就不识别了"。现在三条一起做：

| 时机 | 自动动作 |
|---|---|
| **切出游戏窗口** | **关掉大写锁定**（否则在别的程序里打字全是大写） |
| **切回游戏窗口** | ① **开回大写锁定**（游戏按键绑定与它有关）② **鼠标归位**到左上角（他切出去时鼠标可能停在游戏某个控件上，悬停会改控件外观、干扰画面判据）③ **重新判一次"我在哪一屏"** |
| **在比赛里切出去再回来** | 游戏会停在「**重新开始赛事 / 退出赛事**」这个菜单（挑战计时也停了）→ 认出它、按 **Esc 返回**、**回到比赛继续跑**（这条同时在 A 阶段轮询里生效，不用等他切焦点） |
| **退出程序**（F1 / 停止 / 关窗口 / 跑完） | **关掉大写锁定**（不留大写给他） |

第 ③ 条只做保守动作：**只有确实认出"有弹窗/菜单挡路"才清掉它**（认不出时绝不按回车）。
另外"认不出车格"这一步也接了自愈：先退回已知界面、再重新进一次列表（只试一次）。

日志里对应的事件：`focus_lost` / `focus_gained`（带离开时长、鼠标原位置、界面判定）/
`caps_lock_exit` / `recover_probe`。

> 为什么"切回来不识别"：切出去的这段时间**游戏可能自己暂停/跳了界面**，而程序还按原计划
> 往下走 —— 现在切回来会重新确认一次，配合自愈层就不会一路走错。
> 前提是目标窗口的 `pause on focus loss` 行为你保持游戏默认即可，程序不改游戏设置。

## 挂机防睡 + 状态小窗（2026-10-04 更新口径）

* **晚上挂机口径**：屏幕**允许**按你原来的 15 分钟规则正常变黑 ✓；程序运行期间只按住
  「系统睡眠 / 休眠 / 硬盘断电」（SetThreadExecutionState + PowerSetRequest 双 API，
  **只调电源管理 API，不碰游戏进程** —— 不违反工具层契约），退出自动释放、电源计划改动自动还原。
* 想连屏幕也不让黑：高级设置把 `keep_display_on` 改 True（或系统层面
  `powercfg /change monitor-timeout-ac 0`）。
* 整套防睡想关掉：`--no-keep-awake` 或控制台里取消勾选。
* **兜底**：万一抓帧真的全黑（看不见），会打印提示并**原地等待**（默认无限等、不误操作、
  按键不丢；期间 F1 仍可急停），画面一恢复立即续跑。
* **状态小窗**：默认打开（`--no-gui` 关掉；缺 tkinter 会自动跳过），显示
  状态灯 / 阶段 / 轮次+循环 / 已解锁车数 / 已跑轮数 / 运行时长 / 最近动作。
  置顶显示但**不抢游戏焦点**；**关掉窗口不影响运行**（停止仍然只能靠 F1 / Ctrl+C）。
