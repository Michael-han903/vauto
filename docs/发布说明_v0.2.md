## vauto v0.2 —— 把"失误 / 莫名其妙"逐个修掉

《极限竞速：地平线 6》视觉自动化工具（**截屏 → 模板匹配判断 → 模拟键鼠**，仅用于算法学习）。
> 项目对外名：**基于挑战蓝图的地平线六刷技能点软件**（代号 vauto，见 README 的「命名规范」）。
本版是 **v0.1 → v0.2**：把 **57 次实跑日志**里统计出来的每一处失误都定位到具体代码行并修掉，
另外加了**焦点进出联动**、**比赛暂停菜单**判据，并把打包体积砍掉一半。

### 附件与使用条件

| 附件 | 说明 |
|---|---|
| `vauto-win64.zip` | Windows 免安装包（约 80 MB，含 Python 运行库）。解压到**可写目录**，双击 `vauto.exe` 打开图形控制台 |

* 系统：Windows 10/11；游戏：PC 版、**中文界面、3840×2160**（所有判据模板按此分辨率标定）
* 包里的 `vauto.exe --selftest` 可以直接跑 —— 离线验证判据与流程，**不碰屏幕和键鼠**（以前发布包做不到，本版补上了）
* 第一次用请**先不勾**"真的按键"演练一遍；F1 = 急停；目标窗口不在前台时所有动作自动暂停

## 一、修掉的失误（每一条都有实跑数据支撑，不是猜的）

| 现象 | 根因（实测） | 修法 |
|---|---|---|
| 偶尔"上错车" | 到站身份按"打算去的那格"绑定；而同一格的 ♥ 读数在相邻帧会 **1.000 → 0.554** 跳变 | 改用"**光标实际压着的那格**"绑定身份 + 候选二次确认 |
| 每轮都白扫一遍车库 | `_unreachable` / `_brand_jumps` 的清空写在 per-attempt 循环里，作用域错了 | 提到循环外，一轮只清一次 |
| 鼠标点车格像在瞎点 | 日志统计：**6 次成功 / 87 次没选中 ≈ 7%**；而且"判不出黄框"被当成点中了 | 鼠标点选**默认关**；判不出一律退回方向键闭环复核 |
| 整轮卡在"到不了车辆页"（6/57 次） | 固定只重试 10 次（≈25 秒），而上车加载实测要 **13~18 秒** | 改成**时间预算 45 秒** + 用完先自愈再重试 |
| 停在没人预期的界面就一路乱按 | 只在"预期的几步"判页，没有"我在哪"的概念 | 新增界面**状态标签**（用判据分数向量给这一屏贴标签）+ **自愈层**：认不出时按标签退回已知状态，**认不出绝不按回车** |

## 二、提速

* 车格区 HSV **同帧只算一次**、且只算子区域：**62.5 → 31.6 ms/步**
* 翻屏**一屏只抓一帧**（原来抓两帧，抓一帧实测 84 ms）；新增 `grid_scroll_dwell` 配置

## 三、焦点进出联动（按你的要求新加）

| 时机 | 自动动作 |
|---|---|
| 切出游戏窗口 | **关掉大写锁定**（否则在别的程序里打字全是大写） |
| 切回游戏窗口 | ① **开回大写锁定** ② **鼠标归位**到左上角（切出去时鼠标可能停在某个控件上，悬停会干扰画面判据）③ **重新判一次"我在哪一屏"** |
| 退出程序（含直接关控制台窗口） | 也把大写锁定关掉，不留大写状态 |

四项都有独立开关（高级设置里可单独关）。

## 四、比赛里切出去再回来：认得那个菜单了

比赛里切出去做事，游戏会弹「**重新开始赛事 / 退出赛事**」菜单（挑战计时也跟着停）。
以前没有任何判据认识它 → 程序会一直等结算判据，**最长等满看门狗 3×180 秒**才中止（表现就是"切回来就不动了"）。

* 新增判据 `tile_restart_event` / `tile_exit_event`：正样本 **1.000**，134 帧负样本最高 **0.346**（含正常主菜单截图 → 不会把主菜单误判成比赛菜单）
* 认出后按 **Esc 返回比赛**（**绝不按回车** —— 回车会选中高亮项，可能是"退出赛事"）
* 返回后**重新按住 W**，一直按到比赛结束；A 阶段轮询每帧都查 → 不用干等看门狗

## 五、判据重做：搜索面板标题

`panel_search_title` 的旧模板**几乎是一整条纯柠檬绿按钮** → 归一化相关对任何柠檬绿区域都给虚高分：
实测在**正常主菜单页 0.877**、车库列表 0.789、挑战结算 0.909 上都超过阈值 0.696 —— **等于"永远命中"**。

* 新模板只裁「搜索」两个字（181×102）：真面板 **1.000**，156 帧负样本最高 **0.346**
* 新增 `min_std` 对比度下限：空屏/黑屏不再假命中

## 六、体积与工程

* **exe 813 MB → 333 MB**：金标帧原来在包内两处各拷一份、每类 6 张 → 现在只留一份、每类 3 张
* 新增 `cleanup.py` 清理工具（默认只报告、`--apply` 才动手）：删构建垃圾 / 证据图每目录留最新 40 张 / 金标帧**转 JPEG 不删帧**
  → 本机占用 **3.9 GB → 1.2 GB**（日志正文、累计账本、你的设置一律没动）
* 新增 `golden_frames_min/`（6 张 JPEG，约 7 MB，入库）→ 别人 clone / CI / **发布包里的 exe 也能跑 `--selftest`**
* 全项目统一 `.png/.jpg` 都认（只认 png 会把转成 JPEG 的素材当成"不存在"，表现成 IndexError 或"缺少素材"这种**误导性报错**）
* **CI 增加门禁**：打包后先跑一次 `exe --selftest`，不自检通过不会挂 Release
* 离线自检扩到 **21 节**（新增比赛菜单判据、自愈按键、Esc 后重按 W 的集成测试）；修了两处**偶发假失败**（计时类断言取多次最小值、FocusGuard 用守卫自身判据选窗口）

## 注意 / 已知限制

* 判据是**有限状态机 + 模板匹配**，不是"看懂任意界面"；换分辨率 / 换语言界面需要重新标定。
* 关卡与共享代码由用户自行准备；本工具只负责"重复操作自动化"，不提供任何绕过检测的能力
  （无内存读取 / 进程注入 / DLL 注入 / 驱动加载 / 网络通信）。
