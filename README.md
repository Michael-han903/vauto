## 1. 这个工具是干什么的（作用）

把《地平线 6》里两个**无聊但必须重复**的操作全自动化：

| 阶段 | 做什么 | 判据方式 |
|---|---|---|
| **A：挑战刷点** | 自动跑 EventLab 自制挑战（默认共享代码 `161047605`，8 分钟 / 200 SP），按住 W → 等结算 → Esc 重试，指定轮数 | 结算画面模板（`hint_esc_retry` / `panel_result`） |
| **B：车库加点** | 在「我的车辆」里逐辆挑**没收藏（♥）**的车 → 上车 → 车辆专精页按 `Y` 解锁全部加成 → 回车 → 选「加入收藏」补 ♥ → 换下一台 | ♥ 图标模板 + 「驾驶中」图标 + 「Y 解锁全部加成」提示 |
| **C：只取消收藏** | 逐辆检查车库，把**已收藏**的车取消收藏（**不上车**，速度最快） | 同上，动作换成菜单里的「从我的收藏中移除」 |
| **主循环** | **全自动：花↔刷 循环往复** —— 点数够就加点，点到不足自动切斯巴鲁 22B 去刷挑战，刷完回来接着加，一直循环（F1 停） | — |

配套能力：

* **智能找 22B**：在「制造商」面板里**实时识别**「斯巴鲁」三个字（不写死坐标，车厂顺序随车辆变化也不怕），方向键把高亮挪过去回车 —— 原来要滚 369 列 ≈ 6 分钟，现在十几秒。
* **状态控制台**（GUI，打包成 exe 双击即用）：选目标窗口、阶段、轮数、车数、循环次数、共享代码、挑战时长；实时显示**本次 / 累计运行时长**、轮次、已解锁车数、最近动作、运行日志。
* **高级设置面板**：全部 60+ 个可调参数（安全上限、各类超时、按键映射、坐标、阈值……），可保存成 `vauto_config.json`，下次自动载入。
* **安全机制**：F1 急停（物理键盘监听，立即释放所有按键）；目标窗口不在前台时**所有动作自动暂停**；默认演练模式（只判不按）；防息屏/防休眠；全黑画面自动等待恢复。
* **卡住自愈**：认不出当前界面时，先用判据分数给这一屏贴标签（"我在哪一屏"），再按标签选动作退回已知状态（弹窗按它自己的关法、其余 Esc）；**认不出时绝不按回车**。
* **焦点进出联动**：焦点切出游戏 → 自动关大写锁定；切回来 → 自动开回大写锁定 + **鼠标归位** + 重新确认"我在哪一屏"（切出去期间游戏可能自己暂停了）；**退出程序（含直接关窗口）也会把大写锁定关掉**。四项都在高级设置里可单独关。
* **复盘时间线**：`py -3.14 log_timeline.py` 把一次实跑的 JSONL 日志 + 证据图渲染成一张网页（关键事件高亮、异常清单、判据最高分），"为什么停在这一屏"一眼对得上。
* **离线自检**：`--selftest` 用录制的画面回放整条流程，不碰屏幕和键鼠。

## 2. 适用范围（能用在什么场景）

**适用：**

* 游戏的 **PC 版**，**中文界面**；
* 游戏以 **3840 × 2160** 分辨率运行（全屏或无边框窗口均可）—— 所有判据模板都按这个分辨率标定；
* 单机、单账号、自有存档；
* 场景：
  * 车库里有成百上千台车、想批量解锁技能 / 清理收藏；
  * 需要长时间（几小时）无人值守刷技能点。

**不适用（做不到 / 别指望）：**

* ❌ 其他分辨率（1080p / 2K / 4K 缩放）—— 模板全部要重标定；
* ❌ 英文 / 其他语言界面 —— 多数判据是中文文字模板；
* ❌ 主机版 / 云游戏；
* ❌ 任何需要"看懂任意界面"的任务 —— 这是**有限状态机 + 模板匹配**，不是大模型；
* ❌ 完全无人看管的挂机（虽然能长跑，但建议保留 F1 在手的习惯）。

## 3. 使用条件

### 3.1 硬件 / 系统

* Windows 10/11（只在 Windows 上测试过）；
* 屏幕分辨率 ≥ 3840×2160（游戏窗口客户区就是 3840×2160）；
* 建议关闭系统的显示器休眠 / 硬盘休眠（工具会主动申请防息屏，双保险更稳）：

```bat
powercfg /change standby-timeout-ac 0
powercfg /change monitor-timeout-ac 0
```

### 3.2 两种使用方式

**方式一：直接下载打包好的 exe（推荐给普通用户）**

* 从 Releases 下载 `vauto` 文件夹（约 330 MB，含运行库）；
* 解压到**可写目录**（桌面 / D 盘；**别放 C:\Program Files**，日志要写在旁边）；
* 双击 `vauto.exe` → 图形控制台。

**方式二：从源码运行（开发者）**

```bash
# Python 3.10+（开发用的是 3.14）
pip install numpy opencv-python mss pywin32
python run_vauto.py --list                      # 列出窗口，确认能找到游戏
python run_vauto.py --title "Forza Horizon 6" --phase spend --cars 0 --dry-run   # 演练
python run_vauto.py --title "Forza Horizon 6" --phase both --rounds 4 --cars 0 --cycles 0 --enter-event --live
```

打包 exe：`python build_exe.py`（PyInstaller，约 1 分钟）。

### 3.3 游戏侧准备（很重要）

1. 游戏**窗口标题必须含** `Forza Horizon 6`（默认匹配关键字，可改）；
2. 游戏设为**全屏或无边框窗口**，客户区 = 3840×2160；
3. 开始前手动把游戏切到**主菜单或自由驾驶**（工具会自己按 Esc 找菜单）；
4. 自动进赛事功能需要**共享代码有效**（默认 `161047605`，可在界面里改成你的蓝图代码）；
5. DPI 缩放建议 100%（工具会声明 DPI 感知，但改了缩放请重新确认分辨率）。

## 5. 常见问题与解决办法

> 全部来自实机踩坑记录（含截图证据）。

### Q1：程序"看不见"屏幕 / 判据全是 `nan`
**现象**：日志里所有判据分数都是 `nan` 或异常低，之后盲按按键。
**原因**：抓到了**别的窗口**（比如游戏重启瞬间的小窗口、同名的其他窗口）。
**解决**：工具已内置"画面验货"（尺寸必须是 3840×2160、亮度/方差正常），不符会**拒绝动作**并存证据图到 `logs/frame_sanity_*.png`；先跑 `vauto.exe --list` 确认 hwnd，或把游戏窗口恢复成 3840×2160。

### Q2：晚上挂机 / 屏幕变黑后还能继续跑吗？
**可以，这正是设计目标。**
- 程序运行期间**不拦截熄屏**：15 分钟没操作，屏幕照常变黑（省电、晚上睡觉友好）；
- 但**系统睡眠 / 休眠 / 硬盘断电被按住**：`SetThreadExecutionState` + `PowerSetRequest` 双 API，外加可选的「电源计划托管」（把睡眠/休眠超时改成“从不”，退出自动还原、崩溃有备份还原）；
- 屏幕黑着时游戏仍在渲染，**自动化照常工作**（建议游戏用**无边框窗口**，最稳）；
- 万一个别情况抓帧真的全黑（独占全屏等），程序会**原地等待**（不误操作、按键状态不丢），屏幕一回来立即续跑；默认无限等（`black_wait_max=0`），F1 随时可停；
- 想改成“屏幕也常亮”：高级设置里把 `keep_display_on` 改成 True。

### Q3：动作"卡住"了，其实没卡
**原因**：目标窗口**不在前台**时所有动作会**自动暂停**（防止按键打到别的窗口）。切回游戏窗口就会继续。
切回来时还会自动：开回大写锁定、把鼠标归位到左上角、重新确认一次"我在哪一屏"
（切出去这段时间游戏可能自己暂停了 —— 这正是"回来之后就不识别了"的成因）。
如果在**比赛里**切出去再回来：游戏会停在「重新开始赛事 / 退出赛事」菜单，程序认出它就按 **Esc 返回**
回到比赛继续跑（A 阶段每一帧都会查这两块磁贴，所以不用等他切焦点也能自己走回来）。
另外 F1 监听的是**物理键盘**，脚本模拟的按键不会误触发急停。

### Q4：它不认识"当前驾驶的车"，反复给同一台车加/取消收藏
**原因**：当前车的 ♥ 图标位置和普通车**不一样**（画在"驾驶中"图标左侧，而非车格右下角）。
**解决**：已内置双位置判据 —— 先用「驾驶中」小图标判断是不是当前车，是则看**左侧位**模板、否则看**标准位**模板（两个位置各用 60×60 带上下文的专用模板）。

### Q5：加收藏时弹出「回到嘉年华 / 查看车辆」窗口
**原因**：「选择操作」菜单的项数和内容**随是否当前车变化**：
当前车：`1=加入收藏/从我的收藏中移除`、`2=查看车辆（回车会弹确认窗 ✗）`；
普通车：`1=上车`、`2=加入收藏/从我的收藏中移除`。
**解决**：已按身份计算 ↓ 次数（当前车 ×0、普通车 ×1）；并且**弹窗挡路时绝不按回车**，改用 `↓ → 回车` 选「取消」。

### Q6：找不到 22B / 换车要 6 分钟
**解决**：已加「制造商」面板快路（Backspace 打开面板 → 实时识别「斯巴鲁」→ 方向键导航 → 回车，十几秒）。识别失败会自动**退回原来的逐列扫描**，只会慢不会错。
**注意**：面板里「斯巴鲁」**未选中是白底黑字、选中后变黑底白字** —— 工具同时带两个模板匹配。

### Q7：停下之后「启动」按钮点不动，要退出重进
**原因（历史 bug）**：控制台的状态轮询异常被静默吞掉，按钮永远不刷新。
**解决**：已修（轮询 try/finally 保活 + 按钮独立刷新 + 启动守卫按线程存活判断）。如你手上的版本还有此问题，更新到最新版。

### Q8：B 阶段跑满"安全上限"就收工了
**说明**：`--cars 0` 的**正常**结束条件是：① 撞到「技能点不足」→ 去刷；② 整个列表翻完**绕回开头**且没有可处理的车。`cars_cap`（默认 100000）纯粹是防死循环的保险丝，真打到会**醒目告警**并记 `cars_cap_hit`，别当正常收工。
**收藏清理**有独立上限（默认 10 万，能在高级设置改）。

### Q9：整轮几秒就"结束"了
**排查**：看日志第一条 `[!]` 信息。常见是"换车失败/到不了车辆页/光标没落到车格"—— 都是**界面状态没就绪**。最新版已加"等页面判据 + 光标预检（按 ↓ 叫出选中框）"。
**建议**：把 `logs/run_*.jsonl` 和 `logs/*.png` 证据图一起看，每一步都有判据分数。

### Q10：想自己调参数 / 改判据阈值
* **运行参数**：控制台「高级设置…」（60+ 项，可存 `vauto_config.json`）；
* **判据阈值**：`templates/manual_thresholds.json`（每个模板的 `threshold`）；
* **重新标定**：`python run_vauto.py --probe` 抓帧打分、人工翻页复核；
* **改完代码自检**：`python selftest_flow.py`、`python run_vauto.py --selftest`。

### Q11：2026-10-04 这批修正（把 57 次实跑日志统计之后做的）

| 现象 | 根因（实测数据） | 修法 |
|---|---|---|
| 同一台车反复试、每次白走 30 次按键 | `self._unreachable` 写在"每次尝试"里 → 刚记住"这台走不到"下一屏就被抹掉（一轮里出现 10 次，两次之间隔 46 秒） | 清空动作移到"每次进列表" |
| 上了"另一台车"，加收藏还判失败 | 到站后记的是**打算去**那台的指纹；实测同一格 ♥ 读数帧间从 1.000 掉到 0.554 → 上错车 + 记错指纹 | 到站后**按光标实际压着的那一格**重新绑定身份 + 候选二次确认 |
| 加收藏"明明成了却报失败" | 复核用**过去某一帧**的车名指纹在整屏找格子，列表一滚就找不到 | 改成看**光标那一格**有没有 ♥ |
| 整轮卡在"到不了车辆页"（6/57 次） | 固定只试 10 次 ≈25 秒，上车加载 13~18 秒 + 慢盘就超 | 改**时间预算**（45 秒）+ 用完先自愈再重试一轮 |
| 鼠标点车格像在瞎点 | 成功 6 次 / 没选中 87 次（~7%）；且"判不出黄框"被当成点中了 | 默认关掉鼠标点选；判不出一律退回方向键复核 |
| 翻列表慢 | 每屏抓 2 帧（实测抓一帧 84 ms）+ 每步两次全帧 HSV | 每屏 1 帧；HSV 同帧只算一次且只算车格区（62.5→31.6 ms） |
| 黑屏/空屏时"看不见还乱判" | `panel_search_title` 在纯灰帧上也打 0.909（阈值 0.696）——而且它的模板几乎是一整条**纯柠檬绿按钮**，在**正常剧情页 0.877**、车库列表 0.789 上都超阈值 = 永远命中 | ① 给该判据加 `min_std` 对比度下限；② **模板重做**（只裁「搜索」两个字）：真面板 1.000 / 156 帧负样本最高 0.346；③ 空白帧直接判"认不出" |
| 在**比赛里**切出去再回来，程序不认识了 | 游戏停在「重新开始赛事 / 退出赛事」菜单（挑战计时也停），原来没有任何判据认识它 → A 阶段一直等结算判据，最长等满看门狗 3×180 秒 | 照你指的锚点新增两个判据（`tile_restart_event` / `tile_exit_event`，各 1.000 vs 负样本 ≤0.35）；认出后按 **Esc 返回**回比赛（绝不按回车） |
| 停在没人预期的界面就一路乱按 | 只在"预期的几步"判页，没有"我在哪"的概念 | 新增状态标签 + 自愈层（认不出时按标签退回，**绝不按回车**） |

### Q12：磁盘占用 / 怎么清理（2026-10-04）

这类项目的"占地方"几乎全是**可再生的调试素材**，源码 + 模板 + 文档只有几 MB：

| 目录 | 之前 | 现在 | 是什么 |
|---|---|---|---|
| `logs/` | 1.4 GB | 117 MB | 每次实跑的 4K 证据图（一张 2~10 MB） |
| `dist/` | 1.2 GB | 661 MB | exe（813→333 MB）+ 一个旧发布 zip（328 MB） |
| `golden_frames/` | 1.1 GB | 327 MB | 标定/回放用的 4K 金标帧 |
| 合计 | **约 3.9 GB** | **约 1.2 GB** | |

清理工具（**默认只报告、不动手**）：

```bat
py -3.14 cleanup.py                            :: 先看要删什么（安全）
py -3.14 cleanup.py --apply                    :: 执行
py -3.14 cleanup.py --apply --purge-dist-zip   :: 连旧发布 zip 一起删
py -3.14 cleanup.py --apply --purge-golden     :: 金标帧也删（以后重新标定要重新录素材）
```

> 发布包里的 `vauto.exe --selftest` 也能跑：仓库里另存了一份**最小素材** `golden_frames_min/`
> （6 张 JPEG，约 7 MB），`build_exe.py` 在找不到完整素材时自动用它 —— 所以从 Releases 下载的
> 包也能离线自检。CI 现在把"打包后自检"当**门禁**：不自检通过就不会挂上 Release。

它做三件事，且**绝不碰**源码 / `templates/` / `docs/` / `.git/` / 日志正文（`logs/*.jsonl`）/
累计账本（`ledger.json`）/ 你的设置（`vauto_config.json`）：

1. 删构建垃圾：`build/`、`__pycache__/`、`*.spec`、旧压缩包、探针输出；
2. 证据图瘦身：每个日志目录只留**最新 40 张**（`--keep-images N` 可改；旧的复盘网页会缺图）；
3. 金标帧瘦身：**不删帧**，把大场景里除前 3 张外的无损 PNG 转成质量 95 的 JPEG
   （1.1 GB → 327 MB，**241 张一张没少**，`calibrate.py` 照常能重新标定）。

> 转 JPEG 的安全性实测过：同一帧 PNG vs JPEG 跑全部判据，**最大分差 0.032、零阈值翻转**。
> 顺带发现一类真问题：自检里凡是读金标帧的地方原本只挑 `*.png`，转完之后那批帧会被当成
> "不存在" → `IndexError` / 断言失败（`selftest_vision.py`、`selftest_flow.py` 已改成两种都认）。

### Q14：车库列表的**真实操作模型**（2026-10-04 晚，用户实测口述 → 找车逻辑重写）

用户原话：
> 在列表里面的时候，箭头上下只会在当前列切换，箭头左右会在左右列之间切换，所以你要重新写
> 一下找车的逻辑，抛弃掉鼠标，只用方向键找车，先保持选中框在最上一行，然后逐列移动，观察到
> 屏幕内出现未收藏车辆时先通过方向左右键将其所在列移动到第一列，然后按情况使用上下方向键，
> 当选择框在目标车辆上时，按回车即可选择操作

| 键 | 真实作用（实测） |
|---|---|
| `↑` / `↓` | **只在当前列内**上下切换（**不会**跨列） |
| `←` / `→` | **在左右列之间**切换（选中的那一列永远画在最左边） |
| `Enter` | 选择框压在目标车上时 = 「选择操作」 |

**这条模型解释并修掉了历史上反复出现的"上下横跳"**：
被选中的列永远渲染在最左边 → 光标框的 x 恒定在 ~816（翻遍 30+ 张现场帧都是如此），
而旧代码却在"按行/列像素差推 ↓/↑ 方向"，于是光标在两台相邻候选车之间来回跳。

新版 `_walk_to_tile`（三步，每步等画面**稳定**后再判）：

1. 光标框 x ≠ 目标框 x → 按 `←`/`→` 把目标那一列挪成"选中列"；
2. x 对上 → 按 `↑`/`↓` 把选择框对到目标那一行；
3. 光标框压住目标格 = 到站 → 调用方按回车。

* **鼠标彻底抛弃**（用户明确要求）：原来那段"点车格"（实测命中率 ~7%）已从流程里移除；
* 目标固定按用户口径"**先最左列、同列里最上面**"挑，不再按"离光标最近"；
* 每一步都走 `_settle_after_key()`：真机采样证明**游戏选择光标有 ~2 秒动画**，动画中间读帧会得到
  "光标框消失 / ♥ 读数假跳（0.568→0.986→0.556）" —— 旧代码只等 0.6 秒就判"没动"，于是按反向键
  把光标拽回去（这正是横跳的物理成因）；
* 护栏：同一光标框出现第 3 次 → 判定横跳、放弃这台换下一台（有证据图）；走不动同样有界退出。

> 建模相关代码同步：`flow/nav.py` 的模型（↑/↓ 列内、←/→ 换列）与 `GridModel` 语义已按此改写，
> 旧描述（"↓ 到底会跳到别的列"）已标注**被推翻**。以上全部有自检覆盖（`selftest_flow.py` ①②㉒）。

## 6. 项目结构

```
vauto/            工具层（屏幕捕获 / 模板匹配 / 键鼠仿真 / 焦点守卫）—— 不含业务逻辑
flow/             业务层（配置 / 状态机 runner / 图形控制台 / 高级设置 / 防息屏）
templates/        判据模板 + 阈值标定表（manual_thresholds.json）
docs/             实测要点、运行手册、全流程判据对照表
selftest_*.py     四组离线自检（时序/栈/视觉/流程），改动后必跑
offline_replay.py 录屏回放（不碰真屏幕的整流程自检）
log_timeline.py   复盘：一次实跑的 JSONL 日志 + 证据图 → 时间线网页
run_vauto.py      命令行入口    vauto_gui.py  exe 入口    build_exe.py  一键打包
cleanup.py        磁盘清理（默认只报告；删构建垃圾 / 瘦证据图 / 金标帧转 JPEG）
```

判据约定：**判据不得包含会变化的业务对象**（比如"当前车叫什么名字"），
一切以"跨状态稳定的界面元素"为准；每个判据都要在标定表里有分数和阈值。
